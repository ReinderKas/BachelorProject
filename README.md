## 1.1 - Web Interface
The front end is implemented in Angular. This is a javascript based web application framework. <br>
Working with angular allows me to generate components for different features of the web application. <br>
This means that when a new component is created, it will be no extra work implementing this component in different websites.<br>
For now there are 3 components:
 + **Graph**: The Graph component is a visual representation of the given Feature Model.
 + **UnsatCore**: The UnsatCore component shows the minimal set of Constraints that form the unsatisfiable core of the problem.
 + **Proof**: The Proof component shows the output from the **Z3 Solver** when a Feature Model is unsatisfiable.

 An extra component can _(should?)_ be made for the following:
  + **Proof 2.0**: Show the **Z3 Solver** result in a structured overview.


## 1.2 - API

The backend is implemented in .NET 7.0 (C#)<br>
There is no implementation with a database, as this is not necessary for now. <br>
(The Feature Models that are checked are in the format of String. These are hardcoded into the front-end code to make this process easier.)<br>
As of now there are 3 API endpoints:
 + `/error` : Used for error handling when something goes wrong in the API Logic layer.
 + `/proof` : Used to generate a Z3 model from the given string and return the Proof generated by Z3 as a string as well.
 + `/featureModel`: Used to generate a Feature Model and return all of its Nodes and Constraints.
 + `/unsatCore`: Used to generate an Unsatisfiable Core (aka, minimal conflict set) of the given Feature Model.


## 1.3 - String to Feature Model

In order to convert the given string to a Feature Model, we need some tool to interpret the given string. <br>
I cannot delve too much into the specifics of the implementation, but I can say that a colleague and I have created something that takes a string as input and generates Feature Model that can be converted to something that Z3 understands.

## 1.4 Feature Model to Z3.

Now that we have the Feature Model, we need to generate a Z3 Solver in which we can model this Feature Model.
This can be done with specific rules defined in the `Z3Parser` README.md file.
